GUIDE FOR SCRIPTS AND AI AGENTS
  Each command above has its own detailed help: ktask <command> --help.

CONCEPTS
  Project    A Git repository, identified by its directory (--project, default: cwd).
             init, add, import, check-set and model-default register it on first use;
             every other command fails with exit 3 until it is registered. Each project
             has its own queue and supervisor; several projects run at the same time.
  Instance   ktask and ktask-dev keep separate databases; --paths prints them. The working
             directory never selects the instance.
  Task       A title, a Goal and acceptance criteria (one --criterion each). State only the
             outcome and how to verify it; the agent owns design and implementation.
             Kind ai is run by agents. Kind human is owner work, confirmed with done.
  Category   The work category of an AI task (code, documents, art or your own, see
             category list) supplies its execution, review, validation and remediation
             templates and says whether project checks apply. Placeholders: category
             placeholders. A revision pins the templates it was defined with.
  Lens       An opt-in specialist review (concurrency, security, simplicity or your own, see
             lens list) a task selects with add/edit --lens NAME; each lens reviews the change in
             its own read-only session in place of the single ordinary review, all finish
             before one repair is requested, and findings name their lens. lens defaults sets
             the project's default selection; --no-lenses keeps the ordinary review.
  Revision   Each edit appends a revision. Only a ready (approved) revision runs; a newer
             draft waits for approve or reject while the older ready one stays usable.
  Attempt    One execution: implement, project checks, independent review and validation,
             with up to ten repair rounds. Success commits the change as
             "ktask: task #N, attempt #M". Failed attempts are kept as recorded.
  Current    The first unfinished task in queue order. Only current runs. A failed current
             blocks later tasks until it is retried, stopped or marked done.
  Version    Every task has a version that each change increments. Pass --if-version N,
             with N from show/list, so a change fails with exit 4 if the task moved on.
  Roles      execution, review, validation and remediation; every task needs all four.
             Each role uses its configured model; the same model may serve multiple roles.
             Review and validation still run independently with read-only access.
             planning (project default only) is used by breakdown. Models are written
             PROVIDER/MODEL: codex/gpt-6-sol, claude/sonnet, opencode/VENDOR/MODEL. A bare
             "claude" means claude/sonnet. Providers: codex, claude or opencode.

BEFORE THE FIRST RUN
  - Once per user and instance, save what new projects start with:
        ktask model-default execution --provider claude --model opus --effort high \
            --new-projects
    Repeat for planning, review, validation and remediation; choose each role explicitly.
    Then ktask defaults sets agent network, baseline checks, check timeout, run mode,
    planner approval and delivery mode; ktask defaults --apply copies them to an existing
    project (without --apply it only shows what would change).
  - In each project, a Git repository root with at least one commit and a clean worktree:
        ktask init       registers it with the user defaults, detects a check, lists the
                         project-specific setup left, exits 4 listing anything missing
    --check-command CMD sets the check; --agent-network on lets agents that change the
    project use the network, for example to install dependencies.
  - The provider CLI (codex, claude or opencode) is on PATH and logged in, and bubblewrap
    (bwrap) is installed: review, validation and judges run in a sandbox where the project
    and ktask's own records are read-only, whatever the provider allows.
  Defaults apply only to tasks added later; change an existing task with edit --model.
  Named profiles reuse role models: ktask profile create NAME --from-project, then profile
  select NAME (this project) or profile default NAME (new projects). Models resolve in the
  order user defaults, selected profile, project override (model-default), task models;
  profile effective shows each value and its source, profile inherit clears an override.

TYPICAL SESSION
  ktask --json add --title 'Export CSV' --goal 'Users can export the report as CSV.' \
      --criterion 'Export writes a valid CSV' --criterion 'make check passes'
  ktask --json run --background        # returns once the detached supervisor is up
  ktask --json current                 # the task the runner is on, with attempts
  ktask --json events --after 0        # progress feed; pass next_after on the next call
  ktask --json show 12                 # full record: revisions, attempts, steps, usage
  ktask --json pause                   # pause the runner; waits until it exits; run resumes
  ktask --json stop 12                 # back to Pending; changes stashed; run starts afresh
  ktask --json done 12 --reason '...'  # the owner's verdict; the task goes to History
  Foreground run (no --background) blocks until the queue is done or something needs
  the owner, then prints why it stopped. A detached runner logs to
  <state>/runner-<project id>.log (see --paths).

STATES ("state" in list, show and current; "actions" lists what each offers)
  needs_approval  no approved revision, or a newer draft: approve, reject, edit, move, done
  pending         queued; run, edit, move, cancel, supersede --by IDS, done
  running         an attempt is executing, or waiting for a provider limit (attempt
                  wait_reason "rate_limit", resume_at_ms; it resumes by itself):
                  pause, stop, restart, done
  paused          run resumes the same attempt; edit, stop, restart, done
  needs_input     the agent asked a question: answer ID --text '...'; edit, stop, restart, done
  failed          the last attempt failed and automatic repair stopped (see below):
                  run retries from the checks with restarted limits; edit, stop, restart, done
  done  cancelled  superseded
                  final; listed with --scope history. copy ID [--before ID] queues a new
                  pending task with the same definition.
  stop returns a task to pending: its worker stops, the attempt ends, and uncommitted
  changes are saved as the stash "ktask: task #N attempt #M" (git stash list); the next run
  starts fresh with full limits. done stops a live attempt the same way first.
  restart ID stops the current task, saves its work, and runs from current HEAD; a real
  unpublished checkpoint is retained and rechecked before delivery. A refused action
  exits 4 and names the state and the actions it offers. "status" keeps the stored
  value (new, ready, running, paused, waiting, failed, succeeded, succeeded_override,
  superseded, cancelled).

WHEN EXECUTION STOPS ON A FAILED TASK
  Automatic repair stops only when the attempt budget or the task time limit is used up,
  critical findings remain after ten repair rounds, the failure judge replanned ten times,
  the provider or environment failed three attempts in a row, or five attempts in a row
  failed. Then choose one:
    ktask run                                  retry from the checks; limits restart
    ktask edit ID --attempt-limit 6            or --task-limit off, --model ..., then run
    ktask stop ID                              back to pending; edit it, then run afresh
    ktask restart ID                           recover checkpoint intent and run afresh
    ktask done ID --reason '...'               accept it as done; it goes to History
  Use edit ID --preview-project-defaults to inspect all four effective role settings;
  edit ID --apply-project-defaults copies them.

OUTPUT CONTRACT
  Workers and checks can save flat regular files in KTASK_ARTIFACT_DIR. Files are
  archived per attempt before scratch cleanup, up to 128 MiB each, 1 GiB and 4096 files per attempt.
  Judges start with bounded evidence indexes; full logs stay in the archive.
  ktask evidence FILE --offset 0 --limit 4096 pages text without opening the database.
  Add --search TEXT for literal search; follow next_offset until eof.
  ktask show ID (or current) lists artifact IDs, media types, sizes, SHA-256 digests
  and source trees. ktask artifact ID opens retained UTF-8 text/JSON. Storage retention
  keeps Queue and unresolved-failure evidence; eligible History artifacts are pruned.
  retention DAYS --max-bytes N --max-files N sets finite instance allocation limits.
  The runner cleans eligible closed evidence at queue handoffs and pauses new work
  when protected allocation leaves no capacity. storage previews physical SQLite,
  WAL, artifact, directory and runner log allocation before manual --apply.
  cache lists owned/unowned build caches and provider storage; cache adopt opts a Cargo
  target in, cache clean [--apply] retires obsolete generations, cache limits sets bounds.

  Without --json, output is human text and may change. With --json, stdout carries one
  line:  {"schema_version":1,"ok":true,"data":...}
  and a failure writes to stderr:
         {"schema_version":1,"ok":false,"error":{"code":"...","message":"..."}}
  Mutations return a receipt such as {"action":"revised","id":12,"version":8}; version is
  the task's new version. add and import return {"action":"created","tasks":[{"id","version"}]}.

EXIT CODES
  0  success
  1  database, io or incompatible_database error
  2  usage: invalid arguments
  3  not_found: no database, unregistered project, or unknown task
  4  conflict: stale --if-version, wrong task state, a run precondition (no check, a
     role without a model, dirty worktree, runner already active) or another rule
  Errors carry a message that says what to do next; read it before retrying.

RULES FOR AI CALLERS
  - Mark your changes as AI work: --actor-kind ai --actor NAME. Without it, changes are
    recorded as the human owner.
  - Read before you write: take version from show or list and pass --if-version.
  - Do not edit or commit the project's worktree while an attempt is running, paused or
    waiting; the supervisor owns it. Check with: ktask --json current
  - Agents working inside an attempt cannot manage tasks. They may only file a follow-up
    draft (follow-up), using the callback the supervisor provides.
